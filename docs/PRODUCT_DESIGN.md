# 产品与体验设计 v0.1

## 1. 游戏定位

工作名 **WAR**。单人、可离线玩的原创基地攻防策略游戏，核心乐趣是「用有限金币修筑有取舍的防线，再用不同兵种寻找 AI 基地的薄弱处」。一场战斗约 2–4 分钟；一轮建造、进攻、复盘约 5–10 分钟。目标用户可以在手机上用触控完成全流程，电脑端沿用相同规则。

玩家的两个身份：

- **建造者**：摆放核心、火炮台、机枪台、箭塔和城墙，升级材料与设施，测试自己的基地。
- **指挥者**：选择总人口上限内的兵种，从边缘部署，观察自动寻路和交战，并根据战报调整阵容。

首版不做真人匹配、聊天、公会、抽卡、赛季、宝箱、加速付费或强制等待。未来如加入多人对战，必须重新设计服务器权威结算、反作弊与数据同步，不能把单机存档直接当多人状态。

## 2. 推荐的首版体验闭环

1. 初次进入：20–40 秒引导，展示基地核心、箭塔与 12 段木墙；玩家获得 2,500 金币和 16 人口军营。
2. 建造：玩家可移动赠送设施，花金币建新炮台、补墙或升级；放置时即时预览占地和射程。
3. 配兵：从已解锁兵种中选编，人口不超过军营容量；首版每局免费补充兵种，金币只用于永久建造与升级。
4. 侦察：选择 AI 基地难度，观察完整静态布局、防御覆盖和可部署边界。
5. 战斗：3 分钟内按人口部署；兵种自动按可解释规则移动和交战；允许暂停查看，暂停时模拟不前进。
6. 结算：显示星级、破坏率、金币、阵亡单位数、突破位置、受伤最重炮台和可改进提示。
7. 再尝试：玩家调整阵容或基地；防守测试允许 AI 用同一兵种体系攻打玩家布局。

首版的进攻奖励可重复获取，按 [金币规则](GAME_RULES.md#7-金币与进度)结算；测试防守不消耗金币。退出重进后基地、金币、解锁、设置和未开始的阵容仍在；进行中的战斗可按确定性快照恢复或明确提示该局作废，首版推荐后者，不扣兵种或金币。

## 3. 地图、布局和可读性

- 逻辑地图为 **28×28** 个正方形格；中间 **24×24** 格是基地建造区，四边各 2 格是进攻方部署环。格子坐标从左上 `(0,0)` 起，整数代表格子；实体使用格内连续坐标。
- 基地核心 3×3，炮台与军营 2×2，城墙每段 1×1。固定障碍与建造物不得重叠；部署环不得建造，内部不得部署。
- 单段城墙四向相邻自动连成视觉上的连续墙。规则碰撞仍按每段独立记录 HP 与等级。转角不留肉眼难辨的缝隙，寻路不允许从两个斜邻墙段的夹角穿越。
- 整图应能完整缩小到手机屏幕；触点下方显示高亮格与半透明建筑，放大后可精确微调。最小触控目标约 44 CSS px；缩放、平移、选择和确认不能相互误触。
- 以颜色、形状和图标共同区分三种炮台、墙材与兵种；显示射程圈、危险热区和选中单位目标线，不只依赖颜色。

布阵合法性：基地核心必须存在且只能有 1 个；所有建筑完全在建造区；不重叠；不能超过上限；军营和炮台允许被围墙包围，因为墙是可破坏障碍。保存前检验一个进攻单位至少能从部署环到达某个可攻击目标，必要时允许通过可破坏城墙开路；如果自定义布局异常，给出具体冲突格而非悄悄丢弃数据。

## 4. 界面流程与交互

| 页面 | 必要信息与动作 | 成功标准 |
| --- | --- | --- |
| 主基地 | 金币、基地等级、建造入口、配兵、进攻、防守测试、设置 | 一屏能找到下一步，金币变更即时反馈 |
| 建造模式 | 格线、占地影子、合法/冲突提示、射程圈、撤销、保存 | 未确认的拖动不扣金币；取消恢复原位 |
| 建筑详情 | 名称、等级、当前/下级 HP 或 DPS、升级价格、限制原因 | 一次点击只升级一次；扣费与属性更新原子完成 |
| 配兵页 | 已用/总人口、兵种数量、职责、目标偏好 | 超出人口不允许开始，错误原因直说 |
| 侦察页 | AI 布局、可部署区、危险覆盖、三档难度 | 看得到炮台类型，但不预知 AI 临场选择 |
| 战斗页 | 计时、星级、破坏率、剩余部队、速度 1×/2×、暂停、退出确认 | 即使缩放也能可靠部署到指定格 |
| 战报页 | 胜负、破坏率、奖励、时间线、关键受击来源 | 可一键重试、返回基地并比较上次结果 |

建造操作建议：先选择建筑种类，再触摸地图出现预览，拖动微调，按「放置」确认；移动已有建筑时使用相同流程。城墙可拖线批量铺设，但按每段标价显示总价，超过金币时不允许部分隐性扣费。升级城墙支持多选，同材质与目标级别才可批量升级；混合选中时逐种列出价目。

## 5. 视觉和声音方向（待共创）

建议基调为「边境机械工坊」：木石防线与齿轮、金属炮台同处一个世界，既能容纳箭塔也能容纳机枪。画面用原创、轮廓清晰的插画或像素插画；不同炮台在缩小后仍可凭剪影辨认。战斗特效短、色彩节制，优先保障目标与炮火方向可读。声音按单位部署、命中、墙体破坏、升级、胜负分层，提供静音与音量控制。此方向是方案，最终题材、美术语言和名称由设计者决定。

素材不得临摹其他游戏的建筑轮廓、角色、UI、图标、音效和专有名称；所有素材需记录来源与使用许可。第一阶段允许简单几何占位图，但视觉验收时必须替换为一致的原创素材。

## 6. MVP 与后续

**MVP 必须有**：28×28 地图、建造与存档、基地核心、军营、三种炮台、四种墙材、前四种兵种、三档 AI 基地、玩家进攻、AI 防守行为、AI 主动攻打玩家基地的无金币防守测试、战报、基础经济和手机触控。

**MVP 之后**：两种进阶兵种、正式有奖防守挑战、更多地图地形、挑战任务、美术与音效扩充。防守测试应在完整进攻闭环之后实现，且在 MVP 验收前完成。

明确边界：首版没有实时建造对抗，也没有在线 PvP。后续若选择这些方向，需先回到本文调整核心循环和技术规格。

## 7. 核心设计原则

1. **选择真实**：三塔、四墙、六兵各有用途；不存在一种配置对所有 AI 布局都最优。
2. **规则公平**：玩家与 AI 的单位使用同一属性、碰撞、射程、伤害和人口上限。
3. **失败可学**：战报能说明为什么输，以及下次可采取什么策略，不靠隐藏数值制造难度。
4. **无软锁**：玩家始终有可玩的免费阵容和可攻击目标；金币不足不能阻断继续战斗。
5. **易改参数**：平衡数据单独存放，设计者可以调整价格、HP、AI 权重，而不需要改核心算法。
